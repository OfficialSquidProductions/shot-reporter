# .camreport formats

## Complete open report · schema 2 (Apple build 14+)

The default Save As .camreport on iPhone/Mac exports one complete open report. Reports remain independent local documents: unrelated shooting days or saved reports are not silently grouped by title. The archive includes the exact current and previous schema-1 report snapshots, explicitly added media/attachments/recovery files, all app-owned persistent preferences, earlier imported preference snapshots, and known legacy recovery files for the selected local slot. Imported/current report snapshots are also retained as file references so later edits cannot discard the imported recovery baseline. Files named in take text must be added explicitly through the system picker; no inferred file access or media playback is involved. External OS backups and other reports are outside this scope.

Schema 2 is streamed stored ZIP64, not the schema-1 in-memory ZIP subset. Its strict manifest is `format=org.squidproductions.camreport`, `schema=2`, `scope=complete-open-report`, package UUID, device label, current/previous SHA-256 identifiers, resource/preference state and a unique payload inventory. Only `manifest.json` and `payloads/<64 lowercase SHA-256 digits>` member names are allowed. Manifest/state unknown fields are rejected rather than discarded. All sizes, CRCs, SHA-256 values, local/central headers, non-overlapping contiguous ranges and ZIP64 footer bounds are checked before a preview is shown. Encryption, compression, data descriptors, multi-disk files, directories, symbolic links, aliases and unsafe/duplicate names are refused. There is a 1 TiB total safety cap, 8 MiB metadata cap and at most 19,989 resource references (including recovery baselines), subject to available storage. Reading/writing uses 1 MiB chunks; only bounded metadata/report snapshots are loaded into memory. Checksums are not authenticity signatures or encryption. Treat a received attachment as an untrusted file; the app retains opaque bytes and does not execute them.

Import stages and verifies every payload under content-addressed private names, then presents counts, filenames and preference choices. Open as separate editable report uses a fresh UUID slot, never overwrites or merges an existing report, and inserts current/previous/catalog in one SQLite transaction. File installation uses an atomic same-volume directory move, with rollback on an insert failure. Cancel removes only its own staging directory. Media source files, exports and preexisting reports stay intact. Appearance/detail preferences may be applied after review; all other preferences, including security/updater/platform settings, travel as data and are never activated by import. Earlier source preference snapshots survive subsequent exports when effective device values differ.

Local SQLite schema 4 adds `project_state` to each slot; existing current/previous blobs, deletion dates/tokens and active selection are preserved. Catalog updates check both the report fingerprint and previous catalog to reject concurrent stale changes. Managed files are immutable copies below `ProjectFiles/<local-slot>/<SHA-256>`; selected originals are never moved or erased. Restore copies the complete file set into a new report. Permanent trash removal commits only deleted document rows/markers before deleting that slot’s managed file directory. Active files, external originals, legacy recovery files and exported archives are kept. Old Apple/other-platform clients cannot open schema-2 archives or a schema-4 local database; use the explicitly labeled report-data-only legacy export for portable schema-1 compatibility.

`tools/verify_complete_archive.py --output <new-directory>` compiles current native core code for Mac and a disposable iOS Simulator, checking every model field plus a 35 MiB binary media file, Unicode attachment, complete preference data and recoveries through persistence/edit/export and return import. Swift tests also cover tampering, unsafe metadata, bounded ZIP64 offsets beyond 4 GiB, missing files, stale catalogs, failed imports, cancellation, safe preference application and trash isolation. The exact signed Mac app’s native import picker, verified preview and Save panel export were exercised. Multi-gigabyte throughput, physical iPhone UI and actual AirDrop/iCloud delivery remain field checks.

## Legacy report-data-only export · schema 1

`.camreport` is a proposed Shot Reporter format, not an industry standard. This implementation uses an unencrypted, uncompressed ZIP with exactly `manifest.json` and `report.json`. The maximum archive size is 32 MiB. Only report JSON is included. No paths are extracted to disk during import.

Manifest: `format=org.squidproductions.camreport`, `schema=1`, random `packageID`, stable `reportID`, integer `revision`, originating `device`, `scope=full-report`, and lowercase hexadecimal `sha256` over the report.json bytes. ZIP local headers, central directory, bounds, entry names, duplicates, compression, CRCs and end record are validated. Compressed/encrypted/multi-disk archives and additional entries are unsupported and rejected.

Report: stable `id`, `revision`, project `values`, camera `defaults`, named `profile`, `positions`, ordered `entries`, `history`, `importedPackages`, and legacy `namingTemplate`. Optional legacy `namingSettings` is retained when present. These naming fields remain inert compatibility data rather than exposed controls. `positions` is also retained as compatibility data; every responsibility is always available in the UI. The existing `defaults` map stores the current settings for upcoming takes. Edits to a recorded setting update that take and the corresponding value in `defaults`; earlier snapshots stay unchanged. Returning to app defaults replaces only this map (including a fresh load identity), leaving recorded takes intact. Dictionaries preserve extensible field values. Dates use Foundation's Codable numeric seconds since 2001-01-01 UTC. Entries carry stable `id`, snapshot `values`, sorted `flags`, boolean `reviewed`/`deleted`, and `created`. Report schema structures are strict: future fields that would be lost in a decode/re-encode comparison are rejected. Evolving the schema requires explicit migrations and fixture tests.

Fresh exports receive fresh package IDs. Reimporting the same package ID is a no-op. Entries with new IDs are additions. Existing IDs with different contents are conflicts; current files are never overwritten based on timestamps. Different project IDs cannot merge. Omission is never deletion; only explicit tombstones can represent removed records, and competing tombstone edits are conflicts. Full three-way merge and partial scope are intentionally unavailable in this alpha.

Checksums detect accidental corruption; they are not authenticity signatures. On-device names and role labels describe attribution and do not authenticate a person. Opening separately retains the report's project ID but uses a separate local document slot so both divergent versions survive.

## Report management and production mode

`values.productionMode` is `movie` or `tv`; absent or unrecognized values display as Movie. Movie hides Season and Episode from editing and printable reports without clearing their saved values. Camera roll values remain in legacy maps and editable packages but are no longer shown or required by the digital report screens.

Local SQLite schema 2 adds a `deleted` flag to each document slot. Delete Report changes that flag transactionally and preserves both snapshot blobs. Recently Deleted restores the same slot and snapshots. Deletion rejects a stale confirmation, updates active selection atomically, and leaves exported files unchanged. Deleting the last active report clears the active slot and opens an unsaved blank workspace. Legacy snapshot migration recognizes deleted slots and does not reimport them. This local schema change does not change portable `.camreport` schema 1.


## Legacy iPhone / Mac report-data handoff

The report-data-only legacy export serializes the entire selected Report model, not the visible PDF fields: project and crew values (including custom map values and hidden Movie/TV season/episode), recording defaults, every take and its complete recorded settings/notes, flags, review/deleted state, creation dates, history, imported package IDs, profile, preserved positions and naming settings. A fresh package ID describes the export; the project ID and revision remain unchanged. On the destination, Import Save → Open as separate editable report preserves all incoming values and keeps any destination report independently. A return export uses the same format. Merge is deliberately limited to independent additions and must not be used to replace a whole edited production when conflicts are reported.

One file contains one report/production. It does not bundle camera footage, scripts, attachments, an entire library of reports, local report trash, SQLite previous/recovery snapshots, app appearance/preferences, or external files referenced in text. Schema 1 is capped at 32 MiB and has no encryption. Checksums verify bytes, not delivery; AirDrop/Files/iCloud/email transport and physical-device receipt remain separate from format validation.

`tools/verify_project_handoff.py --output <new-directory>` creates a realistic two-camera/six-take synthetic production, compiles the same current report/exchange/repository code for macOS and an installed iOS Simulator, and checks every model field through native read → persistence → edit → export → Mac persistence/re-export. It creates and removes only its own disposable simulator. Unit tests also exercise the app's FileDocument exporter and Open as separate Store behavior. These tests do not claim a physical iPhone UI or AirDrop delivery was exercised.

## Trash retention (local schema 3)

Schema 3 adds a deletion timestamp and fresh deletion token plus payload-free purged-slot markers. Existing schema-2 trash is dated at migration, giving it a full 14-day grace period. Restore clears its timer; deleting again starts a new timer/token. Startup/active/hourly cleanup removes only deleted slots aged at least 14 × 24 hours. Future dates do not expire; an inconsistent active trash slot stops cleanup. Clear Trash requires an exact confirmed snapshot; restoration, re-deletion or newly deleted items invalidate stale confirmation. Removal and payload-free markers commit in one SQLite transaction, preserving active reports and their current/previous snapshots on failure. The markers prevent legacy migration files or stale app instances from resurrecting removed local slots. Independently importing an exported backup opens a fresh slot.

Permanent removal deletes the app's current and previous report payloads from its local library and cannot be undone in the app. Previously exported files, legacy recovery files, external/device backups and filesystem snapshots are independent and are not erased. This is application deletion, not a forensic disk-erasure guarantee. Development, tests and native acceptance use explicit synthetic roots; no owner trash is cleared during verification. Old app builds cannot open schema 3. This cleanup policy remains in schema 4; portable format changes are described above.


## Report display names · build 15

Production title (`values.title`) is the single stored source for the report name. The active picker, header, saved/deleted report lists, deletion confirmation and import previews derive their display text from it. Missing, empty and whitespace-only titles display “Untitled production”; leading/trailing whitespace is trimmed only for presentation. The original stored title remains intact. No name field, ID rewrite, local schema change or portable-format change is introduced. Editing the title uses the normal saved revision/history path, preserves the local slot/project identity, and keeps the previous recovery snapshot. Existing export filename and naming-template rules remain unchanged.
