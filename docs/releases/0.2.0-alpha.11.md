# Shot Reporter 0.2.0-alpha.11 · Apple build 14

Save As .camreport now exports the complete open report with its explicitly added media, attachments, app preference snapshot, previous local report snapshot, imported recovery copies and known legacy recovery files. Add Media, Add Attachments and Add Recovery File in Saves copy selected files into the report without moving or editing the originals. Each saved report remains independent; unrelated reports are not silently bundled by production title.

Imports verify all file sizes, CRCs and SHA-256 hashes before offering a preview. Open as separate editable report creates a fresh local copy, preserves current and previous snapshot bytes and leaves existing reports intact, even when identity/title match. Cancel leaves saved reports unchanged. The complete preference data travels with the report; the import switch applies only appearance/detail settings. Updater, account and security settings are never activated by imported preferences. Earlier preference snapshots are retained when exporting after a device changes settings.

Media names typed into takes do not grant file access: add the actual files before exporting. Files are opaque bytes; this does not add footage playback or restore the removed Footage tab. Recovery copies can be saved separately, and readable report snapshots can open as separate reports. Restoring a previous report keeps its project files. Clear Trash removes the deleted report's app-managed file copies after confirmation; source files and exported archives stay intact. Automatic cleanup still uses the 14-day deletion policy.

Both iPhone and Mac require this build or newer for complete schema-2 archives. The legacy report-data-only export remains available for older clients, with its original 32 MiB report-data limit. Complete archives use streamed, uncompressed ZIP64 with a 1 TiB total safety limit, 8 MiB metadata limit and up to 19,989 file references, subject to available local/destination storage. Only regular files are accepted; folders, aliases and symbolic links are refused. Unsupported future metadata fails explicitly without dropping fields. Large transfers may require substantial local space and time; AirDrop/iCloud transport success is a separate check.

Validation and distribution status are recorded in the release acceptance files. Synthetic native Mac → iOS Simulator → Mac tests cover every report-model field, a 35 MiB binary media file, a Unicode attachment, preferences and recovery snapshots. Physical iPhone UI, multi-gigabyte media throughput and real AirDrop delivery remain owner field checks. Windows/Android binaries have not been updated for schema 2; use the explicitly labeled legacy export for those clients.
