# Shot Reporter 0.2.0-alpha.13 · Apple build 17

Report names include the recorded shooting day, for example Angels on High Day 1. The picker, header, saved/deleted report names, import previews and PDF heading use the same rule. New blank reports begin at Day 1. Exports add a portable Day suffix when the chosen naming template does not already include a day token; existing files/templates are not rewritten.

Start New Day at the bottom of Today and Saves previews the next day/date and creates a separate report with a fresh identity. Production/crew/general values, production mode, report/naming preferences and general camera settings are retained. Reference attachments are copied and verified. Previous-day takes, media, recoveries, imported-package history and per-setup measurements stay with the earlier report. A fresh load ID and empty mag are used. The previous day remains unchanged. A stale source or failed file/database operation stops the new-day operation; no existing report is overwritten. Review the new date/day in Today, especially after gaps in the shooting schedule. Non-numeric old day labels require explicit correction before advancing; unknown dates default to today's UTC date.

Selected flags, detail/mode/measurement choices, sidebar destinations and saved report rows have a filled dark-green state with readable white text and/or a checkmark. Measurement display defaults to feet/inches for each report; Settings offers meters or centimeters. Recognized explicit units convert for display and PDF without rewriting the stored measurements. New bare numeric input uses the selected unit. Original unqualified or unrecognized legacy text stays as entered with a notice; units are never guessed for existing data. Unit selection travels in the report. Display rounding does not accumulate when switching units.

The project time-base and varispeed/sensor-FPS boxes are removed from app and PDF forms. Existing values are preserved in report maps, local snapshots and .camreport archives; legacy columns remain in CSV. Optional per-take Light meter at subject fields record a reading in f-stop, EV, lux or foot-candles, plus subject/context. Record ISO/shutter context for exposure readings. Meter unit selection labels the entered reading; it does not convert exposure or illuminance. The lens T-stop remains separate, and a new take/day starts without a meter reading. The PDF has a separate LIGHT AT SUBJECT block beside recording/exposure settings.

Meter units and exposure context are based on [Sekonic's light-meter specifications](https://sekonic.com/sekonic-l-858d-u-speedmaster-light-meter/), which distinguish exposure, cine and incident illuminance modes. No automatic metering calculation, sensor hardware integration or meter-to-T-stop calibration is implied.

Validation includes 92 Swift tests, 26 packaging checks, forced-crash persistence, native iOS Simulator/Mac archive/new-day/unit/meter checks, and rendered PDF inspection. Signed Mac UI, real signed updater installation and actual TestFlight availability are recorded in acceptance/status assets. Local database schema remains 4; complete .camreport remains schema 2 and the legacy report-data-only format remains schema 1. Development/testing use disposable reports and never purge owner trash. Physical iPhone UI and AirDrop delivery remain device field checks. Windows/Android binaries are unchanged.
